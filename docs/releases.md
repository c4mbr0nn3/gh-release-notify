# Releases

Releases are cut locally and published by a tag-triggered GitHub Actions
workflow. There is no `workflow_dispatch` trigger: pushing a release tag is the
only way to publish.

## Cutting a stable release

From a clean `main`:

```bash
./scripts/release.sh --dry-run     # preview version, level, changelog
./scripts/release.sh               # infer the bump and release
./scripts/release.sh --minor       # or --major / --patch
```

The script:

1. Checks that `git-cliff` 2.14.1 and `cargo-release` 1.1.5 are installed.
2. Infers the SemVer bump from conventional commits (breaking → major,
   `feat` → minor, everything else → patch) unless a level is passed.
3. Runs the verification gate: `cargo fmt --check`,
   `cargo clippy -- -D warnings`, `cargo test`.
4. Runs `cargo-release`, which updates `Cargo.toml` and `Cargo.lock`, prepends
   the changelog section, commits `chore: release v{version}`, tags
   `v{version}`, and pushes `main` plus the tag.

`--dry-run` prints the prospective tag, bump level, and changelog without
invoking cargo-release. The pre-release hook runs even under cargo-release's
dry-run, which is why the script never uses it.

## Cutting a release candidate

```bash
./scripts/release-rc.sh              # next derived stable base
./scripts/release-rc.sh --base 1.3.0
./scripts/release-rc.sh --dry-run
```

The tag is `vX.Y.Z-rc.N`, with N starting at 0. The base comes from
`git cliff --bumped-version` unless `--base` is given; N is the next free number
across local and remote tags.

The script is **tag-only**:

- It refuses a dirty tree, a non-`main` HEAD, or an existing tag.
- It never commits and never changes `Cargo.toml`, `Cargo.lock`, or a version
  file.
- RC tags never render a `CHANGELOG.md` section (`cliff.toml` `tag_pattern` is
  stable-only) and never create a GitHub Release. Their commits fold into the
  next stable release.
- CI publishes `vX.Y.Z-rc.N`, `X.Y.Z-rc.N`, and a moving `rc` tag, never `latest`.

When the RC is validated, cut the stable release with `./scripts/release.sh`.

## Workflow

`.github/workflows/release.yml` runs on a `v*` tag push and:

1. Checks out with full history and installs the pinned Rust 1.98.1 toolchain.
2. Runs the gate.
3. Runs a blocking Trivy filesystem scan for `HIGH,CRITICAL` findings.
4. Builds and pushes a multi-arch (`linux/amd64,linux/arm64`) image to
   `ghcr.io/c4mbr0nn3/gh-release-notify` with SBOM and provenance.
5. Builds an amd64 image locally and runs a blocking Trivy image scan with
   `--ignore-unfixed` (the pushed ref is a multi-arch manifest list that Trivy
   cannot scan reliably).
6. Uploads both SARIF reports to the Security tab.
7. For stable tags only: installs git-cliff 2.14.1 and creates a GitHub Release
   with a git-cliff-generated body.

Tags that are neither `vX.Y.Z` nor `vX.Y.Z-rc.N` fail at the version step and
publish nothing.

## Image tags

Stable `vX.Y.Z`:

- `vX.Y.Z` — git tag verbatim; use for pinning.
- `X.Y.Z` — SemVer without the `v`.
- `latest` — newest stable release.

Release candidates additionally publish `vX.Y.Z-rc.N`, `X.Y.Z-rc.N`, and a
moving `rc` tag pointing at the newest RC.

## Pulling the image

`docker-compose.yml` pulls from GHCR by default:

```bash
docker compose pull
docker compose up -d
```

To pin a release, edit the compose file:

```yaml
    image: ghcr.io/c4mbr0nn3/gh-release-notify:v1.1.5
```

For a local build, run `docker compose up --build`; the `build: .` directive is
retained as a fallback.

## Rules

- **Lockstep toolchain pin**: the CI toolchain (`1.98.1`) and the Dockerfile
  builder (`rust:1.98.1-slim-trixie`) move together in one commit. Builder and
  runtime stay on the same Debian release (both trixie) or the glibc-linked
  binary fails to start.
- **Fix forward**: after a post-tag CI failure, do not delete the tag or revert.
  Cut a new patch release.
- `release.toml` is the single source of truth for cargo-release behavior. Do not
  duplicate it under `[package.metadata.release]` in `Cargo.toml`.

## Other scripts

- `./scripts/backfill-release-notes.sh` repairs GitHub Release bodies for
  existing tags.
- `./scripts/test-container.sh` is the podman smoke test; see
  [Operations](operations.md#container-smoke-test).
- `CHANGELOG.md` is generated by git-cliff and committed by the release flow.
